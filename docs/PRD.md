# 用记录修正通勤选择

使用者要决定的是“明天选哪条路、几点出门、多花的钱值不值”。产品先用两条路线快速估算，再用同方向、相近时段的3–300条实际耗时，逐步替换记忆中的三点数值。

## 一条完整任务

输入常见耗时和单程费用 → 对比时间/波动/费用 → 查看每条路线的依据与记录数量 → 设定模型内尾部阈值 → 试行并记录新耗时 → 导出当前输入、模型版本和结果。四城预设只演示方法，载入需确认覆盖，随后直接进入比较。

## 不能省掉的判断

- 估算与记录分开。前者是PERT假设，后者是经验重采样；增加模拟次数不能弥补缺少雨天、延误等观察。
- 观察0次迟到不能说风险0。显示原始计数和Wilson区间，并说明出门时间也从同批记录选择，不能算独立验证。
- 三个维度允许并列；同费用不误称更贵。没有舒适度、天气、换乘体验等资料时，不替用户断言唯一最优。
- 返程同分布、日期独立是假设。当前界面阈值1%–20%只是模型内设置，无法承诺未来准点。

## 状态与恢复

数字有草稿态：Enter或失焦确认、Esc取消；空白不变零，错误提示写明仍按已确认值计算。提交后输入与结果引用不同时即进入更新态，150ms后计算完成；旧结果可看但不能导出。

图上只有红线附近能启动拖动。移动时预览，不重采样；松开后按统一范围提交，取消手势不提交。数字框提供同一操作的键盘方式。

有效草稿自动本机保存。损坏/越界/重复ID不静默恢复，也不自动覆盖原记录；用户可继续计算、导出，或明确选择替换。浏览器禁用存储不妨碍本页比较。

## 为什么绑定路线随机流

一次移除不应让其他路线看起来变快。采样种子由路线身份确定，四城完整预设保留既有随机流以便对照历史产物；自定义ID用稳定哈希。固定种子只是可复现，不是交通模型验证。
