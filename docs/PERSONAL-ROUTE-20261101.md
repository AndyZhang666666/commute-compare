# 个人条件与试行复查

状态：开发分支，本地审阅；当前 main 与线上版本保持。

## 这次解决的问题

同一张时间费用表，不同预算和出门习惯的人会作出不同选择。本轮在既有通勤模拟之上加入两个可选条件：月预算、最早愿意出门时间。逐路线说明条件差，不合成一个替用户判断的分数。用户仍可以明确接受取舍。

比较、建议出门时间与选择放在同一个工作区，详细尾部图表和城市预设收起。结果旁可添加试行耗时：先预演变化，再应用到对应路线；前三条积累中不冒充已校准分布。记录达到三条，确认后使用原有经验重采样。

## 保留与恢复

- 改回估算必须明确确认；个人记录保留，可恢复。整理替换记录也保留前一份有效记录。
- 快速估算与高级三点值在个人记录生效时不能直接编辑，先回路线输入切换来源。费用仍可改，不会移除记录。
- 个人条件、记录及修订号进入决策签名。任何改变都让原选择成为待重新确认的旧快照。
- 旧草稿和v1决策继续可读；新决策为v2。条件缺省表示未设置。浏览器拒绝保存时仍可完成选择与导出。
- 预演绑定当时路线与到达设置；期间输入改变，必须重新预演。超过300条不自动删除旧记录。

## 视觉与交互选择

保留路线桌的蓝灰时间区间，主数字和操作保持墨色，颜色只标识路线与冲突。设计参考 design-taste-frontend 的 Achromatic ledger（seed 1103523177），保留现有配色与字体；主要对象是路线、时间区间和实际条件差。主工作区不再通过三个同权选项卡切换。手机优先完成路线条件与选择，次级依据可展开；记录预演只用短反馈动画，减少动态效果下移除位移。

## 检查与边界

`node --test scripts/test-personal-route.mjs` 检查条件边界、少量记录积累、三条开始校准、估算/记录恢复、坏记录不应用、旧草稿/v1决策读取、条件改变后快照失效。原分布与决策检查继续保留。

原模型版本不变；本轮未接地图或模型，不验证真实未来迟到率。月度按往返、返程同分布计算，预算与最早出门条件只是用户给出的边界。浏览器任务验收另记，不将开发者操作成功率写成真实用户完成率。
